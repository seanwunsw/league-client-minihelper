## Root Causes Identified & Fixed

### 1. **Hardcoded Install Path** ❌ → ✓ Fixed
**Problem:**
- Code only checked `C:\Riot Games\League of Legends\lockfile`
- User had League installed at `D:\game\Riot Games\League of Legends (PBE)`
- No fallback or discovery mechanism

**Solution:**
Implemented multi-method install directory discovery:

1. **RiotClientInstalls.json** (`C:\ProgramData\Riot Games\RiotClientInstalls.json`)
   - Parses JSON metadata for `patchlines` with `product_install_full_path`
   
2. **Product Settings YAML** (`C:\ProgramData\Riot Games\Metadata\league_of_legends.*\*.product_settings.yaml`)
   - Extracts `product_install_full_path` from YAML files
   
3. **Drive Scanning**
   - Scans all available drives (C:\, D:\, E:\, etc.)
   - Checks common paths:
     - `Riot Games\League of Legends`
     - `Riot Games\League of Legends (PBE)`
     - `game\Riot Games\League of Legends`
     - `game\Riot Games\League of Legends (PBE)`
     - `Games\Riot Games\League of Legends`
     - `Program Files\Riot Games\League of Legends`
     - `Program Files (x86)\Riot Games\League of Legends`
   
4. **Default Location Fallback**
   - Still tries `C:\Riot Games\League of Legends\lockfile` as last resort

**Code Changed:** `lcu/client_finder.py` - Added `discover_riot_install_paths()` function

---

### 2. **Missing Process Detection** ❌ → ✓ Fixed
**Problem:**
- Only looked for `LeagueClientUx.exe` process
- User's system had `LeagueClient.exe` instead
- Process detection was too narrow

**Solution:**
- Now detects both `LeagueClientUx.exe` AND `LeagueClient.exe`
- Updated `find_client_process()` to check both process names

**Code Changed:** `lcu/client_finder.py` - Updated `target_processes` list

---

### 3. **Elevation/Permission Issues** ❌ → ✓ Fixed
**Problem:**
- Tried to read process command line (`--app-port`, `--remoting-auth-token`)
- When League runs elevated (or from different user), `psutil` can't read cmdline
- `Win32_Process.CommandLine` was empty, causing detection to fail
- No fallback mechanism

**Solution:**
- Process detection now has multi-stage fallback:
  1. Try to read cmdline args (if accessible)
  2. If cmdline unavailable, get process exe path
  3. Use exe path to find install directory
  4. Look for lockfile in that directory
- Added detailed logging at each step

**Code Changed:** `lcu/client_finder.py` - Enhanced `find_client_process()` with fallback logic

---

### 4. **Silent Crashes / No Logging** ❌ → ✓ Fixed
**Problem:**
- All logging went to console only
- When exe was closed, all logs were lost
- User couldn't debug why it wasn't working
- No persistent log file to inspect after crashes

**Solution:**
- Added rotating log file: `LoLAutoAccept.log`
  - Placed next to the executable
  - Max size: 5 MB per file
  - Keeps 3 backup files
  - Logs to both console and file simultaneously
- Added detailed logging of all discovery attempts:
  - Each method tried (process, RiotClientInstalls.json, drive scan, etc.)
  - Success/failure for each attempt
  - Port, password (redacted), and install directory when found
  - Why detection failed

**Code Changed:** `main.py` - Updated `_setup_logging()` method

## Technical Details

### Discovery Method Priority (in order):

1. **Running Process Detection** (fastest if League is open)
   - Detect `LeagueClientUx.exe` or `LeagueClient.exe`
   - Try to read cmdline for port/token
   - If cmdline unavailable, use exe path to find lockfile

2. **Install Directory Discovery** (if process not detected)
   - Parse RiotClientInstalls.json
   - Parse product_settings.yaml files
   - Scan all drives for common paths
   
3. **Default Location** (last resort)
   - Check `C:\Riot Games\League of Legends\lockfile`

### Lockfile Format:
```
LeagueClient:<pid>:<port>:<password>:<protocol>
```
Example: `LeagueClient:12345:54321:mypassword:https`

### Log File Location:
- Next to the executable: `LoLAutoAccept.log`
- Rotating: 5MB max, 3 backups (LoLAutoAccept.log.1, .log.2, .log.3)
