# v0.1.2 Analysis - What Was Actually Wrong

## User's Bug Report Analysis

From the log excerpt (`D:\download\LoLAutoAccept.log`):
```
13:08:53,694 lcu.websocket_client ERROR Error processing WebSocket message: Expecting value: line 1 column 1 (char 0)
```

This ERROR was logged repeatedly - **this was the smoking gun**.

---

## Root Causes Discovered

### 1. **WebSocket Subscribe ACK Handling** ❌ CRITICAL BUG
**What was wrong:**
```python
def on_message(ws, message):
    try:
        data = json.loads(message)  # ← CRASHES on empty ACK frames
```

**What happens:**
- When we send `[5, "OnJsonApiEvent_lol-matchmaking_v1_ready-check"]` to subscribe
- LCU WebSocket sends back an **empty acknowledgment frame** (empty string or whitespace)
- `json.loads("")` raises `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`
- This was logged as ERROR but **didn't crash the app**
- However, it meant **message parsing was broken from the start**

**The fix:**
```python
def on_message(ws, message):
    try:
        # Skip empty messages (subscribe acknowledgments)
        if not message or not message.strip():
            logger.debug("Received empty WebSocket message (likely subscribe ack)")
            return
        
        data = json.loads(message)
```

**Impact:** This was likely the **primary reason** ready checks weren't accepted - the message handler was failing on every ACK, which may have broken subsequent event handling or caused the subscription to not complete properly.

---

### 2. **LCU Protocol Parsing** ❌ INCORRECT PROTOCOL UNDERSTANDING

**What was wrong:**
The original code assumed the event data structure was directly in `data[2]`:
```python
if opcode == 8:  # Event message
    event_data = data[2]
    uri = event_data.get('uri', '')  # ← This was correct
```

But we weren't logging enough to verify the actual structure received from LCU.

**The fix:**
```python
if opcode == 8:  # Event message
    event_name = data[1]  # ← Added: capture event name
    event_data = data[2]
    uri = event_data.get('uri', '')
    event_type = event_data.get('eventType', '')
    
    logger.debug(f"WS Event: opcode={opcode}, name={event_name}, uri={uri}, type={event_type}")
```

**LCU WebSocket Protocol (confirmed):**
- Format: `[opcode, eventName, eventData]`
- For events: `[8, "OnJsonApiEvent", {uri: "/lol-matchmaking/v1/ready-check", eventType: "Update", data: {...}}]`
- Event subscription: `[5, "eventName"]`
- Subscribe ACK: empty frame (not JSON)

**Impact:** We were missing the event name logging, which would have helped diagnose issues faster. The actual parsing logic was correct, but we added more debugging.

---

### 3. **Ready Check Event Not Received** ⚠️ UNKNOWN (possibly never queued)

From the log: **No "Ready check event: state=..." line was ever logged.**

This means either:
1. The WebSocket subscription didn't complete (due to ACK error above)
2. The user didn't actually queue/get a ready check in that 1-minute window
3. The event URI or subscription name was wrong

**The fix:**
```python
# Log EVERY ready check event at INFO level
logger.info(f"Ready check event received: uri={uri}, eventType={event_type}, state={state}, playerResponse={playerResponse}")
```

Plus added **HTTP polling fallback** (1-second interval):
```python
def _poll_ready_check(self):
    while self.running:
        time.sleep(1)
        state_data = self.api_client.get_ready_check_state()
        if state_data:
            state = state_data.get('state', '')
            if state == 'InProgress' and player_response == 'None':
                logger.info("Ready check detected via HTTP polling, accepting...")
                self._accept()
```

**Impact:** Even if WebSocket events are missed, HTTP polling will catch the ready check. This is a **belt-and-braces approach**.

### 4. **Accept POST Not Logged** ❌ NO VISIBILITY

**What was wrong:**
```python
def accept_ready_check(self) -> bool:
    result = self.post('/lol-matchmaking/v1/ready-check/accept')
    if result is not None:
        logger.info("Successfully accepted ready check")  # ← Only on success
        return True
    return False
```

This didn't log:
- The HTTP status code
- The response body
- Failure reasons

**The fix:**
```python
def accept_ready_check(self) -> bool:
    logger.info(f"Sending accept request: POST {endpoint}")
    response = self.session.post(url, auth=self.auth, json={}, timeout=5)
    status_code = response.status_code
    
    logger.info(f"Accept response: status={status_code}, content={response.text[:200]}")
    
    if 200 <= status_code < 300:
        logger.info(f"✓ Successfully accepted ready check (HTTP {status_code})")
        return True
    else:
        logger.warning(f"Accept request returned non-2xx status: {status_code}")
        return False
```

**Impact:** Now we'll see **exactly** what the LCU API responds when we try to accept.

### 5. **Discovery Spam Every 5 Seconds** ❌ CONFIRMED FROM LOG

From the user's log:
```
then every ~5 s until 13:09:59:
lcu.client_finder INFO Found lockfile: port=57656, install_dir=E:\games\League of Legends
lcu.client_finder INFO Success: Found client via running process
```

**What was wrong:**
```python
def run(self):
    while self.running:
        if not self._connect_to_client():  # ← Called every 5 seconds
            time.sleep(5)
            continue
        time.sleep(5)  # ← Then sleep, then loop back
```

Every loop called `_connect_to_client()`, which called `get_client_info()`, which logged discovery.

**The fix:**
```python
def _is_connected(self) -> bool:
    return (self.current_client_info is not None and 
            self.api_client is not None and 
            self.ws_client is not None and 
            self.ws_client.connected)

def _connect_to_client(self) -> bool:
    # If already connected and WebSocket is still alive, don't re-discover
    if self._is_connected():
        return True
    
    # Only log when state changes
    if self.current_client_info and not self._is_connected():
        self.logger.info("Connection lost, attempting to reconnect...")
```

**Impact:** Discovery is now only logged when:
- First connection
- Connection state changes (lost/regained)
- Port/password changes

The 5-second loop now does a **cheap health check** instead of full re-discovery.

### 6. **Multiple Instances** ❌ CONFIRMED FROM LOG

From the log:
```
13:08:53,623 __main__ INFO LoL Auto-Accept Helper Started (v0.1.1)
13:08:53,669 __main__ INFO LoL Auto-Accept Helper Started   <- 2nd instance 46ms later
13:09:03 a 3rd instance starts
```

**What was wrong:**
No single-instance guard. Double-clicking the exe or PyInstaller's onefile bootloader could launch multiple instances.

**The fix:**
```python
def check_single_instance():
    if not WINDOWS:
        return None
    
    mutex_name = "Global\\LoLAutoAcceptHelper_SingleInstance"
    kernel32 = ctypes.windll.kernel32
    mutex = kernel32.CreateMutexW(None, True, mutex_name)
    
    if kernel32.GetLastError() == ERROR_ALREADY_EXISTS:
        return None  # Another instance running
    
    return mutex  # Keep alive

# In main:
mutex = check_single_instance()
if mutex is None and WINDOWS:
    show_info_message("Already Running", "Check system tray...")
    sys.exit(0)
```

**Impact:** Second launch now shows a message box and exits cleanly.

## What I Believe Was the Primary Issue

**Most likely:** The **empty WebSocket ACK error** broke the subscription process, so ready check events were **never received**.

Evidence:
1. ERROR logged on every subscribe attempt
2. No "Ready check event: state=..." ever logged
3. WebSocket message parsing crashed on empty frames

**Secondary issues:**
- Discovery spam made logs noisy
- No visibility into accept POST results
- Multiple instances confused the situation
